\chapter{Hypothesis Testing: Chance or Real Effect?}
\label{ch:hypothesis}

Life is full of situations where we must decide whether an observed
result reflects a real effect or simply random chance. Is that coin
you're flipping really unfair, or did it just happen to land heads
several times in a row? Did a new medicine help patients recover, or
would they have improved anyway? Is one website design better than
another, or did it get lucky in a single experiment? In the previous
two chapters, we learned how probability describes uncertainty and how
randomness behaves when we collect data. Now we can use those ideas to
answer a new question: when should we attribute an observed result to
chance, and when should we view it as evidence of a real effect? In
this chapter, we learn how hypothesis testing uses a baseline
explanation to judge whether an observed result is too surprising to
blame on chance alone. Along the way, we'll introduce null and
alternative hypotheses, explore p-values and permutation tests through
simulation, study the possibility of making incorrect decisions, and
examine what happens when many hypotheses are tested at the same time.
Throughout the chapter, we will treat hypothesis testing as a game of
testing a claim: nature gives us data, and we ask whether those data
could have come from a world in which the null hypothesis is true.


\section{Basic Concepts}

Every hypothesis test begins with two competing explanations. The
\emph{null hypothesis}\index{\emph{null hypothesis}}, written $H_0$,
is the baseline explanation. It often says that there's no real
difference, no effect, or no pattern beyond random variation. The
\emph{alternative hypothesis}\index{\emph{alternative hypothesis}},
written $H_1$, describes the effect or pattern we are looking for if
the baseline explanation does not fit the data. In many textbooks, you
will see the phrase \emph{under the null}; it simply means ``assuming
that $H_0$ is true.''

For example, suppose researchers are studying a new drug. The null
hypothesis might say that the drug has no effect compared with a
placebo. The alternative hypothesis might say that the drug does have
an effect. In an A/B test for a website, the null might say that two
page designs lead to the same sales rate, while the alternative says
that one design changes the sales rate.

The same setup appears in many other settings. Scientists might ask
whether the observed increase in global temperature could be explained
without human activity. A hospital might ask whether its 30-day
readmission rate is higher for one group of patients than for another.
A school might ask whether a new tutoring program improved test scores.
The details change, but the structure is the same: start with a
baseline explanation, then ask whether the data is too surprising for
that explanation.

This is the first move in our game. We describe the null world before
we look at the data, so that we have a fair standard for judging what
we observe.

The logic of a hypothesis test is:
\begin{enumerate}
\item Assume the null hypothesis is true.
\item Work out what kinds of data would be common under that assumption.
\item Compare the observed data with those possibilities.
\item If the observed data is very unusual under $H_0$, reject $H_0$.
\end{enumerate}

\subsection{Assume the Baseline, Then Check the Data}

Hypothesis testing is a little like proof by contradiction
\citep{reeves1980hypothesis}. In a mathematical proof by
contradiction, we start by assuming the opposite of what we want to
show. If that assumption leads to an impossibility, then the original
statement must be true.

In hypothesis testing, we also start with an assumption: the null
hypothesis. Then we ask what kinds of data we would expect if that
assumption were true. If the observed data is very far from what the
null hypothesis predicts, we reject $H_0$.

The difference is that statistics cannot give us the certainty of a
mathematical proof. Random events can produce surprising results. A
fair coin can land heads 8 times in 10 flips. A useless drug can look
helpful in one small experiment. So rejecting $H_0$ doesn't prove
$H_1$ beyond all doubt. It means that the observed data is unusual
enough under $H_0$ that we decide to reject the baseline explanation.
Similarly, failing to reject $H_0$ doesn't prove that $H_0$ is true.
It only means that the data didn't give enough evidence against it.

As a warm-up, imagine flipping a fair coin 20 times and seeing 16
heads. One way to judge this result is to build a pretend world where
the coin is fair. We could simulate many sets of 20 fair-coin flips and
count how often 16 or more heads appear:

\subsection{Type~I and Type~II Errors}

Because data is random, hypothesis tests can make mistakes. A
\emph{Type~I error}\index{\emph{Type~I error}} occurs when we reject
the null hypothesis even though it's true. This is also called a false
positive. For example, we might conclude that a drug works when it
doesn't.

The probability of making a Type~I error is controlled by the
\emph{significance level}\index{\emph{significance level}}, denoted by
$\alpha$. A common choice is $\alpha = 0.05$, which means that if
$H_0$ is true, the test is designed to reject it incorrectly no more than
5\% of the time.

A \emph{Type~II error}\index{\emph{Type~II error}} occurs when we fail
to reject $H_0$ even though there really is an effect. This is also
called a false negative. If the probability of a Type~II error is
$\beta$, then $1 - \beta$ is called the \emph{power}\index{\emph{power}}
of the test. Power measures how well the test detects a real effect.

These two errors are the basic trade-off in hypothesis testing. If we
make the test stricter, we reduce false positives, but we may also miss
more real effects. If we make the test easier to reject, we catch more
real effects, but we also risk more false alarms.


\begin{example}[Lady tasting tea]
R. A. Fisher's ``Lady Tasting Tea'' experiment, described in his 1935
book \emph{The Design of Experiments}~\citep{fisher1935design}, is an
early and elegant example of formal hypothesis testing
\citep{salsburg2002lady}. Fisher described a colleague at Rothamsted
Experimental Station who claimed she could tell by taste whether milk
or tea had been poured first into a cup. To test the claim, he prepared
eight cups: four with milk poured first and four with tea poured first.
The cups were presented in random order, and the lady was told that
there were four of each kind. Her task was to identify the four cups
with milk poured first. Under the null hypothesis, $H_0$, she was
guessing. Fisher then calculated how often a guesser could do as well
as she did purely by chance.

Here the claim is that the lady can tell the difference. The null-world
replay is a set of guesses, and her number of correct answers is the
result we compare with those guesses.

If her performance was highly unlikely under $H_0$, we would reject it
in favor of the alternative, $H_1$, and say that the data give evidence
that she may have the claimed ability. This decision could still be
wrong: a lucky guess could lead to a Type~I error. Conversely, failing
to reject $H_0$ could be a Type~II error if she really had the ability
but the experiment did not provide enough evidence. The example shows
why hypothesis tests are decisions made under uncertainty, not
mathematical proofs.
\end{example}


\subsection{Test Statistic and P-Value}

In hypothesis testing, a \emph{test statistic}\index{\emph{test statistic}}
is a numerical summary of the data used to evaluate the null hypothesis,
$H_0$. It captures the part of the data that matters for the question
we are asking. The choice of test statistic depends on the specific
hypothesis and the structure of the data. Before looking at the data,
we choose a \emph{rejection region}\index{\emph{rejection region}}:
values of the test statistic that will count as unusually extreme. A
test rejects $H_0$ if its test statistic, denoted by $T$, falls into
this region. The chance that $T$ falls in this region when $H_0$ is
true is the Type~I error rate. We control this chance with the
\emph{significance level},
typically denoted by $\alpha$. This threshold is usually chosen to be
small, such as 0.05 or 0.01, to limit the chance of making a
Type~I error.


The \emph{p-value} gives a graded version of this idea. It
is the probability, under $H_0$, of getting a test statistic as extreme
as or more extreme than the one we observed. A small p-value means the
observed result would be rare under $H_0$, so it gives evidence against
it. If the p-value is less than $\alpha$, we reject $H_0$; otherwise, we
fail to reject it.


The p-value is often misunderstood as the probability that $H_0$ is
true given the data. This is incorrect. The p-value assumes that
$H_0$ is true and measures how surprising the observed data is under
that assumption. This mistake is widespread, even among statistically
trained researchers
\citep{falk1995significance}. Understanding that the p-value reflects 
compatibility between the data and the null hypothesis---not the truth of 
the hypothesis---is essential for proper statistical reasoning.

Here is a useful check: if a p-value is 0.03, it doesn't mean there's
a 3\% chance that $H_0$ is true. It means that results at least this
extreme would occur about 3\% of the time among all possible results if
$H_0$ were true.


\begin{example}[Lady tasting tea -- continued]

In the Lady Tasting Tea experiment, the test statistic $T$ is the 
number of cups the lady correctly identifies as having been prepared 
with milk poured first. The total number of cups is an even number $n$, 
with exactly $n/2$ prepared milk-first and $n/2$ tea-first. Importantly, 
the lady is told in advance that there are exactly $n/2$ of each type, 
and she is required to label exactly $n/2$ cups as milk-first. Under the 
null hypothesis $H_0$, she is assumed to be guessing. In this setup, 
it can be shown that the distribution of $T$ under $H_0$ follows a 
\emph{hypergeometric distribution}\index{distribution!\emph{hypergeometric}}, 
and large values of $T$ provide stronger evidence against $H_0$.

To carry out the test, we fix a significance level $\alpha$, such as
$0.05$, representing the maximum tolerable probability of a Type~I
error. We then define the \emph{rejection region}, consisting of
values of $T$ that are considered too extreme to plausibly occur under
$H_0$. Suppose we reject $H_0$ only when $T = n/2$—that is, only if
the lady achieves a perfect classification. The probability of this
outcome under $H_0$ is $\Pr(T = n/2) = 1 / \binom{n}{n/2}$.


For example, suppose $n = 8$ and the lady correctly identifies all 
$4$ milk-first cups. The observed test statistic is 
$T_{\text{obs}} = 4$, and the p-value is 
\[
  \Pr(T \ge T_{\text{obs}} \mid H_0) = 1 / \binom{8}{4}
  = 1/70 \approx  0.0143.
\]
Since this p-value is smaller than the commonly used significance
level $\alpha = 0.05$, we would reject $H_0$ and conclude that her
performance is unlikely to be due to guessing.

We can check this exact calculation with a simulation: let a guesser
pick 4 cups at random out of 8 and see how often all 4 match the true
milk-first cups.

This empirical proportion, \inlnR{```cat(p_tea)```}[teasim], is close
to the exact value $1/70 \approx 0.0143$, confirming that random
guessing produces a perfect classification about as often as the
hypergeometric formula predicts.

The same simulation can record the number of correct guesses in every
trial, not just whether all four guesses are correct:

Now increase the number of cups to $n = 10$, with the lady again
achieving a perfect identification of the $5$ milk-first cups. The 
p-value is
\[
  \Pr(T \ge 5 \mid H_0) = 1 / \binom{10}{5}
  = 1 / 252 \approx 0.0040.
\]
This smaller p-value gives even stronger evidence
against~$H_0$---suggesting that her performance is highly unlikely to
be the result of chance guessing and that she may indeed have the 
ability to tell the difference.
\end{example}

\section{Permutation Tests}

The Lady Tasting Tea example is one example of a general family of
tests known as \emph{permutation tests}\index{test!permutation}. The
basic idea is simple: if the labels in the data could be shuffled
without changing the meaning of the problem, then those shuffled
versions represent possible worlds in which the null hypothesis is
true. A permutation test asks how unusual the observed result looks
compared with those shuffled worlds.

The game is the same as before, but we now build the null world by
shuffling the data instead of listing every possible outcome.

\subsection{Permutation under Exchangeability}

A permutation test relies on \emph{exchangeability}. This means that
under the null hypothesis, the labels attached to the data could have
been swapped without changing the story. For example, if we test a
drug on two groups, and if treatment and control labels are exchangeable
under $H_0$, then any difference between the groups is treated as
random variation rather than a real treatment effect.

Shuffling is not automatically valid just because a computer can do it.
In a simple two-group test, exchangeability usually means that the two
groups have the same distribution under $H_0$, not merely the same mean.
If the groups have different spreads or other important differences,
unrestricted shuffling may create the wrong null world. The study
design tells us which labels can legitimately be shuffled.

We can always shuffle the labels many times, whether or not $H_0$ is
true; shuffling is just a mechanical operation. What exchangeability
gives us is the right way to interpret the result. If $H_0$ is true,
every shuffled arrangement is just as likely as the original one, so
most shuffled datasets will not look as extreme as the observed data.
For each shuffled dataset, we
calculate the same test statistic that we calculated from the real
data. This gives us a picture of what the test statistic would look
like if $H_0$ were true.


By pooling all the data and randomly reassigning the group labels, we
simulate what the data might look like if $H_0$ were true. Each
permutation represents a possible null-world arrangement of the data,
and the distribution of the test statistic across these permutations
forms the \emph{sampling distribution under
  $H_0$}\index{sampling distribution!under $H_0$}. Comparing the
observed test statistic to this distribution allows us to calculate
its p-value, which quantifies how extreme the observed result is
under~$H_0$.


In the Lady Tasting Tea experiment, the null hypothesis
$H_0$ says that the lady is guessing. Under this assumption, all
possible arrangements of the cups are equally likely. Shuffling the
labels gives an exact picture of chance guessing.

Similarly, suppose we compare the mean outcome in a treatment group
with the mean outcome in a placebo group. If the treatment has no
effect and the groups were formed in a way that makes their labels
interchangeable, then the treatment and placebo labels are
exchangeable. The distribution of the shuffled differences in means
shows what kinds of differences we could see by chance.


Sometimes the total number of possible shuffles is too large to list.
In that case, we use a random sample of shuffles and let those sampled
arrangements stand in for the full set.


\subsection{Monte Carlo Approximation}

When it's not practical to use every possible permutation, we can use
a \emph{Monte Carlo approximation}\index{Monte Carlo approximation}.
That means we draw many random permutations and use them to approximate
the sampling distribution under $H_0$. The more permutations we draw,
the closer the approximation gets to the exact permutation test.

\begin{example}[Permutation test for two-group comparison]
Suppose we have two groups of data, $x_1$ and $x_2$, with sample sizes
$n_1 = n_2 = 30$. We will look for evidence that group 2 has a larger
mean than group 1. If $H_0$ is true, there's no real difference between
the groups, so the observed difference in the sample means,
$\bar{x}_2 - \bar{x}_1$, is simply due to chance. Here $\bar{x}_1$ and
$\bar{x}_2$ are the sample means of the first and second groups.

In this version of the game, the claim is that group 2 has a larger

Permutation tests use different assumptions from many formula-based
tests. They can be useful when we don't want to assume a particular
population distribution, such as a normal distribution, but we still
need a valid exchangeability argument. A small
p-value means that the observed statistic is unusual among the shuffled
versions of the data. That gives evidence against $H_0$.

The key idea isn't the shuffling itself, but what the shuffling
represents. Under $H_0$, the labels are supposed to be arbitrary. If
that is true, then the shuffled datasets are reasonable versions of the
world where the null hypothesis holds. The observed dataset is then
compared with this collection of null-world datasets. If the observed
test statistic is near the edge of that collection, the data is
telling us that the null explanation may not be true.


\section{Properties of Hypothesis Tests}

\subsection{Size and Power}

Hypothesis tests are often judged by two properties: size and power.
Size tells us how often the test cries wolf. Power tells us how often
the test finds a real effect when one is there.

At this point, we have a way to play the testing game. We now ask how
well the game works over many repetitions: does it raise false alarms
too often, and does it find real effects when they exist?

Imagine testing a new tutoring program. We could first simulate many
studies in which the program has no effect and record how often the
test rejects the null hypothesis. Then we could simulate many studies
in which the program really does help and record how often the test
detects that effect. These two repeated games describe different parts
of the test's behavior.

Recall that $\alpha$, the significance level, sets the allowed
probability of a Type~I error when $H_0$ is true. The actual long-run
false-positive rate is called the \emph{size} of the test. For
instance, if $\alpha = 0.05$, a well-calibrated test should falsely
reject $H_0$ about 5\% of the time when $H_0$ is true.

As before, if $\beta$ is the probability of a Type~II error, the
\emph{power} of the test is $1 - \beta$: the probability of correctly
rejecting $H_0$ when there's a real effect. Larger samples, larger
true effects, and less variable data usually lead to higher power.

When two tests have the same size, the test with higher power is
usually preferred. But there's a trade-off. Reducing $\alpha$ lowers
the chance of a false positive, but it can also make real effects
harder to detect. Increasing the sample size is one of the most direct
ways to gain power without raising the false positive rate, but it's
not the only way: as the next example shows, choosing a test better
suited to the data can also increase power at the same $\alpha$ and
sample size.

Here is another way to remember the difference. Size describes how the
test behaves when there's nothing to find. If $H_0$ is true and
$\alpha = 0.05$, a valid test shouldn't cry wolf too often. Power
describes how the test behaves when there's something to find. A test
with low power may miss a real effect, especially when the sample is
small or the data is noisy.

This is why designing a study matters before the data is collected.
If the sample size is too small, even a real effect may be hard to
detect. If the significance level is too strict, false positives become
less likely, but the test may also miss more real effects. Good testing
is therefore not only about choosing a formula. It's also about
understanding the errors we're willing to risk.

In the next example, we'll illustrate these
concepts by comparing two common methods for two-sample comparison:
the t-test and the Wilcoxon test (which is based on the ranks of the
data and can be viewed as a permutation test on those ranks). Using
simulations, we'll examine their size and power under different
conditions and demonstrate how their performance varies.

\section{Multiple Testing}

The logic of a p-value works well when we test one idea at a time.
Things change when we test many ideas at once, because now we have many
chances to see a small p-value by chance. To see why this gets tricky,
let's run a simulation.

In the previous section, we repeated one testing game to study its
long-run behavior. In practice, we may instead play many testing games
at once by asking many questions of the same data. That creates a new
chance for false discoveries, even when every null hypothesis is true.

\begin{example}[20 Ineffective Drugs]
We begin with a simple story: a laboratory screens 20 new drugs to
see whether any of them improves a health score compared with a
placebo. Unknown to us, none of the drugs actually works. By
simulating this world, we can watch what happens when we run many
independent tests in parallel.


We first write a function that performs one full screening round,
returning 20 p-values from 20 two-sample t-tests.
\runR{Code/hypo-multiple.R}{hypo-multiple}
\showChunk{R}{Code/hypo-multiple.R}{do1screen}


Even though all drugs are useless, some p-values will be surprisingly
small: in this one run, the smallest of the 20 p-values is
\inlnR{```cat(round(min(pvals_demo), 3))```}[minpvaldemo], and
\inlnR{```cat(sum(pvals_demo < 0.05))```}[countbelowdemo] of the 20
fall below 0.05, purely by chance. To understand this more
systematically, let's repeat the entire screening many times.
\showChunk{R}{Code/hypo-multiple.R}{pvalues}


A histogram provides a clear view of the behavior of p-values under pure
noise:
\showChunk{R}{Code/hypo-multiple.R}{hist}

The shape in Figure~\ref{fig:ch5:pvalues} is roughly flat, as expected
when every null hypothesis is true. But the more interesting question
is: How many significant drugs appear in each experiment?

\begin{figure}[H]
\includegraphics[width=0.6\textwidth]{images/chapter_5/hypo-pvalues.pdf}
\caption{P-values from 40,000 tests where every null hypothesis is true}
\label{fig:ch5:pvalues}
\end{figure}

Let's count how many of the 20 p-values fall below 0.05 in each
experiment.
\showChunk{R}{Code/hypo-multiple.R}{sigcount}

Figure~\ref{fig:ch5:sigcount} shows that although all 20 drugs are
useless, many experiments still produce one or two ``significant''
hits. That is the tricky part: once we give ourselves 20 chances, a
small p-value in one of them is no longer surprising. A \emph{false
discovery}\index{false discovery} is a result we call significant even
though its null hypothesis is actually true. In this example, every
significant drug is a false discovery, and the chance of seeing at least
one is high:

\begin{figure}[H]
\includegraphics[width=0.6\textwidth]{images/chapter_5/hypo-sigcount.pdf}
\caption{Relative frequency of the number of significant results in each
20-drug experiment under pure noise}
\label{fig:ch5:sigcount}
\end{figure}

\showChunk{R}{Code/hypo-multiple.R}{meansig}

Across the 2,000 simulated screenings, the fraction with at least one
significant drug is
\inlnR{```cat(mean(sig_count >= 1))```}[meansigval], which closely
matches the theoretical probability that at least one out of 20
independent tests is significant at the 0.05 level when all null
hypotheses are true. Under $H_0$, each test independently avoids being
significant with probability $1 - 0.05 = 0.95$, so all 20 tests avoid
significance with probability $0.95^{20}$, and at least one test is
significant with probability $1 - 0.95^{20} \approx 0.6415$.

This is one of the main traps of multiple testing: even when nothing
is real, running many tests makes a false discovery likely.

This simulation is not a complete drug study. In real medical research,
a small p-value would not by itself show that a treatment is safe,
useful, or worth giving to patients. Researchers would also examine the
size of the effect, its uncertainty, possible side effects, and how the
study was designed. The example isolates one problem: the risk of false
discoveries when many questions are tested at once.
\end{example}

\subsection{The Smallest P-Value}


Every experiment has an apparent ``best'' drug, the one with the smallest
p-value.
Let's look at that distribution.
\showChunk{R}{Code/hypo-multiple.R}{minp}

Figure~\ref{fig:ch5:minp} shows that tiny p-values (like 0.01 or
0.005) appear quite often---even though nothing is real. This doesn't
mean the minimum p-value is useless; indeed, there's a long history of
using extreme values such as the smallest p-value as a valid test
statistic, provided we take into account how many tests were performed.

\begin{figure}[H]
\includegraphics[width=0.6\textwidth]{images/chapter_5/hypo-minp.pdf}
\caption{Smallest p-value from each 20-drug experiment under pure noise}
\label{fig:ch5:minp}
\end{figure}


The problem arises when we look at many tests, take the smallest
p-value, and then interpret it as if it came from a single test. In
that naive view, we're ignoring the fact that we gave ourselves many
chances to see something ``exciting.'' One way to correct for this is
the Bonferroni method, which we try next.


\subsection{When Some Effects Are Real}

Now let's simulate a world where 4 out of the 20 drugs truly have an
effect: their health score has a true mean of \code{effect = 0.5}
(with \code{sd = 1}, this is a moderate, half-standard-deviation
shift), while the other 16 drugs remain useless, as before.

\showChunk{R}{Code/hypo-multiple.R}{do1screen_alt}

We compare two strategies:

\begin{enumerate}
\item Uncorrected testing: p-value $< 0.05$
\item Bonferroni correction: p-value $< 0.05/20$
\end{enumerate}

Bonferroni correction divides the significance level by the number of
tests (20 here), so each individual test needs a much smaller p-value
to be declared significant. We do this because each test is another
chance to make a false alarm. If we run $m$ tests and use level
$\alpha/m$ for each one, then even in the worst case the chance of at
least one false positive is no more than $m(\alpha/m)=\alpha$. In
plain language, we raise the bar for each test so that the total risk
across all tests stays under control. The price of being stricter is
that we may also miss some real effects. We simulate many experiments
and count true positives (TP) and false positives (FP).

This is a bound, not usually the exact probability. If several tests
produce false alarms in the same experiment, adding their probabilities
can count the same experiment more than once. That can make the sum
larger than the true chance of at least one false alarm. The bound still
works when the tests are related to one another.

\showChunk{R}{Code/hypo-multiple.R}{altresults}

Averaged over the 1,000 simulated experiments, uncorrected testing
finds about
\inlnR{```cat(avg_results["TP_unc"])```}[avgtpunc] of the 4 real
effects but also picks up about
\inlnR{```cat(avg_results["FP_unc"])```}[avgfpunc] false positives
among the 16 useless drugs. Bonferroni correction finds only about
\inlnR{```cat(avg_results["TP_bonf"])```}[avgtpbonf] of the real
effects, but nearly eliminates false positives, with about
\inlnR{```cat(avg_results["FP_bonf"])```}[avgfpbonf] on average.
Uncorrected tests find many real effects but also many fake ones.
Bonferroni greatly reduces false positives, but also misses some real
drugs. The simulation reveals a simple trade-off:

Reducing false discoveries often reduces real discoveries too.
That is the cost of being cautious: when we make it harder to call a
result ``significant,'' we also make it harder to catch the real
signals hiding in the data. Bonferroni is useful when avoiding false
alarms matters most, but it is not free. The more we protect ourselves
from mistakes, the more careful we have to be about missing genuine
effects.



These experiments show the main trap of multiple testing: once we give
ourselves many chances, a small p-value is no longer unusual. We must
judge each result in the context of all the tests we ran, rather than
in isolation. Adjustments like Bonferroni reduce false discoveries, but
they also make true effects harder to detect.

Hypothesis testing and estimation answer different parts of the same
question. A test asks whether the data are difficult to explain under a
baseline claim. It does not tell us how large the effect is or whether
the effect is large enough to matter. This distinction is the difference
between \emph{statistical significance}\index{statistical significance}
and \emph{practical significance}\index{practical significance}.
Estimation addresses those next questions by giving us a plausible
value for the effect and a measure of how uncertain that estimate is.

\section{Summary}

In this chapter we learned the basic game of hypothesis testing:
state a null hypothesis, work out what the data should look like if
that null were true, and then ask whether the observed result is too
surprising to leave the null in place. We defined test statistics and
p-values, and we saw why a p-value is not the probability that $H_0$
is true. It is a measure of how well the data fit the null.

We also looked at Type~I and Type~II errors, along with size and
power. These ideas explain the trade-off in every test: we want to
avoid false alarms, but we also want to catch real effects. The
two-sample comparison showed that a test works best when it matches
the data. With heavy tails, the rank-based Wilcoxon test kept much
more power than the t-test.

The Lady Tasting Tea, two-group permutation, and family-clustering
examples showed how shuffling or random relabeling can build the null
world directly from the data. These tests avoid a normality model, but
they still depend on a valid exchangeability argument. The multiple-
testing examples showed that when we test many hypotheses at once, small
p-values appear even when nothing is real. Corrections such as
Bonferroni reduce false discoveries, but they also make true effects
harder to detect. In the next chapter, we shift our attention to
estimation---how to infer unknown quantities from data and measure how
accurate these estimates are.
